# AcademicTok

A Reddit-style doomscroll for academic papers. Each "subreddit" is a research
field; each "post" is an LLM-written summary of a paper sourced from Semantic
Scholar. Python/Flask backend + Astro frontend.

See [`design_doc.md`](design_doc.md) for the original idea and
[`implementation.md`](implementation.md) for the full design.

## Architecture

```
Semantic Scholar API ──(1 req/s)──► Ingestion worker
                                          │
                                  Ollama (summarize + classify)
                                          │
                                       SQLite  ◄──► Flask API (:8080)
                                                         │ JSON
                                                  Astro frontend (:4321)
```

- **Ingestion** (offline): fetch papers → (when an open-access PDF exists) read
  its full text and pull figures → summarize + classify into a field with a
  local LLM (Ollama) → store in SQLite. New fields are created by the LLM when a
  paper doesn't fit an existing one. Detailed summaries are grounded in the full
  PDF text (falling back to the abstract) and may include LaTeX equations.
- **Serving** (Flask): reads only from SQLite, returns JSON feeds.
- **Auth**: Firebase (Google sign-in). Subscriptions are stored server-side,
  keyed by Firebase UID.

## Prerequisites

- Python 3.11+
- Node 18+
- [Ollama](https://ollama.com) running locally with the model pulled:
  `ollama pull qwen3.5:9b`
- A Semantic Scholar API key
- Firebase project `academic-tok` with the Google sign-in provider enabled, and
  the Admin SDK service-account key saved as `authkey.json` (git-ignored).

## Setup

### Backend

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env          # then fill in SEMANTIC_SCHOLAR_API_KEY
python db.py                  # initialize the SQLite schema
python seeds.py               # insert the seed fields
```

### Frontend

```bash
cd frontend
cp .env.example .env          # already pre-filled with the academic-tok web config
npm install
```

## Running

**1. Ingest some papers** (needs Ollama running + the S2 key set):

```bash
source .venv/bin/activate
python scripts/run_ingest.py --limit 10                 # all seed fields
python scripts/run_ingest.py --field queueing-theory    # one field
python scripts/run_ingest.py --query "graph neural networks" --limit 15
```

**2. Start the API** (port 8080):

```bash
source .venv/bin/activate
python app.py
```

**3. Start the frontend** (port 4321):

```bash
cd frontend && npm run dev          # development
# production:
cd frontend && npm run build && node ./dist/server/entry.mjs
```

The frontend is server-rendered (Astro + Node adapter) so Reddit-style paths
resolve on demand. Open <http://localhost:4321>. Sign in with Google to subscribe
to fields and use the **Subscribed** feed; the **Discover** feed works signed-out.

### Browsing

- Posts are cards; **click a card** to open the post's own page with a long,
  thorough summary (generated by the LLM at ingest, backfilled on first view for
  older papers). When the paper has an open-access PDF, the page also shows
  **figures** pulled from it and renders any **LaTeX equations** with MathJax.
- **Reddit-style routes:** `/r/<field>` shows only that field's posts;
  `/r/<field>/<post-id>` is a single post. The **Fields** page lists every field;
  click one to open `/r/<field>`.

## Admin dashboard

`/admin` is a GUI for running ingestion (instead of the CLI). It is restricted
to allow-listed admins:

- Allowed emails live in the secret file `admin_emails` (git-ignored), one per
  line. The email must match the Google account used to sign in.
- The backend verifies the Firebase token **and** that its verified email is in
  the list (`auth.require_admin`): unauthenticated → 401, signed-in but not
  allow-listed → 403.

From the dashboard you can ingest all seed fields, a single field, or a custom
query (with limit / min-citations), watch the job run, and view the recent
ingestion log. The "Admin" nav link only appears for admins. Ingestion runs in a
background thread, so the request returns immediately and the page polls for
status.

Each run shows a **status card**: a spinner while running, how many papers were
fetched, a green progress bar tracking how many have been through the LLM
(`processed / fetched`), per-paper counts (ingested / skipped / errors), and a
red message if it failed. Multiple concurrent runs are tracked together.

Admin API: `GET /api/admin/check`, `GET /api/admin/fields`,
`POST /api/admin/ingest`, `GET /api/admin/ingest/<job_id>`,
`GET /api/admin/jobs`, `GET /api/admin/log` — all require an admin token.

## API

| Method | Route | Auth | Purpose |
|---|---|---|---|
| GET | `/api/health` | – | liveness |
| POST | `/api/verifyUserId` | token | verify token + provision user |
| GET | `/api/fields` | – | list fields with post counts |
| GET | `/api/fields/<slug>` | – | feed for one field |
| GET | `/api/papers/<s2_paper_id>` | – | full paper/post detail (incl. figures) |
| GET | `/media/figures/<file>` | – | a figure image extracted from a PDF |
| GET | `/api/subscriptions` | yes | list the user's subscriptions |
| POST | `/api/subscriptions` | yes | subscribe `{ slug }` |
| DELETE | `/api/subscriptions/<slug>` | yes | unsubscribe |
| GET | `/api/feed?mode=mixed` | optional | discovery feed (weighted to subs when signed in) |
| GET | `/api/feed?mode=subscribed` | yes | feed from subscribed fields only |

Auth is sent as `Authorization: Bearer <idToken>` (+ `uid` query param) for GET,
or in the JSON body (`{idToken, uid}`) for POST — same convention as the
reference app.

## Notes

- Semantic Scholar is rate-limited to **1 request/second** (enforced
  process-wide in `ingest/semantic_scholar.py`).
- Ollama "thinking" mode is disabled in requests (`think: false`); reasoning
  models otherwise return empty completions under `format: json`.
- Ingestion is run manually via the CLI / admin dashboard; scheduling can be
  added later.
- Open-access PDFs are parsed with PyMuPDF: full text grounds the detailed
  summary and embedded figures (size-filtered to drop logos/glyphs) are saved
  under `MEDIA_DIR` and served at `/media/figures/`. All PDF work is best-effort
  — a missing or unreadable PDF falls back to the abstract.
- Figure **captioning** is optional and off by default (`VISION_MODEL` empty);
  set it to a vision-capable Ollama model (e.g. `gemma4:26b`) to enable it. The
  dense `qwen3.5:9b` is text-only, so figures display without captions there.
- MathJax is self-hosted under `frontend/public/mathjax/` and loaded only on the
  post page (`useMath`); equations are re-typeset after the summary is fetched.
